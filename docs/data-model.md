# Vouch data model (v1)

This document lists every entity in the v1 database: its owning module, its keys and
indexes, the invariants the database enforces, and its retention. The SQL lives in each
module's `migrations/` folder and is the final word; this document explains it.

Related decisions: [ADR 0003](adr/0003-schema-and-role-per-module.md) (schema and role per
module), [ADR 0004](adr/0004-uuidv7-keys-with-public-id.md) (UUIDv7 keys),
[ADR 0005](adr/0005-hash-partitioning-from-the-start.md) (hash partitioning) and
[ADR 0006](adr/0006-no-cross-schema-foreign-keys.md) (no cross-schema foreign keys).
Reference design: `docs/ARCHITECTURE.md` section 7.

## Conventions

- **Keys:** primary keys are UUIDv7, generated by the application (Postgres 17 has no
  `uuidv7()`). The only exception is `platform.outbox.id` (`bigserial`). Clients only see
  `identity.users.public_id`, which is random.
- **Time:** every timestamp is `timestamptz`.
- **Foreign keys:** never across schemas. Inside a schema, only on low-volume tables (listed
  per table below). Cross-module consistency comes from events and the nightly consistency job
  (Phase 10).
- **Personal data:** no plaintext email is stored anywhere. `email_hmac` is
  HMAC-SHA256(server secret, normalised email).
- **Published views** (`*_v`) are the only cross-module read path. They are read-only for
  everyone, including the owning module.

## Global invariants

| Invariant                                 | Enforced by                                                                                                                                                                         |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Users are 18+ at sign-up                  | `identity.users_adult_at_signup` CHECK (birth date at least 18 years before the UTC sign-up date), plus the domain rule in Phase 5. Under-18 sign-ups are refused and never stored. |
| A pair can match only once                | `matching.matches_pair_unique` on `(user_low, user_high)` with `matches_canonical_order` (`user_low < user_high`)                                                                   |
| Unmatch is permanent                      | `matching.matches.unmatched_at` is set and the row is never reused; like rows stay, so the pair never reappears                                                                     |
| A message is stored once per client retry | `chat.messages_client_msg_unique` on `(conversation_id, client_msg_id)`                                                                                                             |
| Message sequence is per conversation      | Primary key `(conversation_id, seq)`; `chat.conversations.last_seq` is incremented with `RETURNING` (Phase 9)                                                                       |
| One swipe per (swiper, target)            | Primary key `(swiper_id, target_id)` on `matching.swipes`                                                                                                                           |
| Passes are deleted after 30 days          | Nightly batched delete per partition (Phase 8), using `swipes_passes_created`                                                                                                       |
| At most one active ban per user           | `safety.bans_active_user` partial unique index                                                                                                                                      |
| An active profile is complete             | `profiles.profiles_active_complete` CHECK (name, gender and preferences set)                                                                                                        |

## Roles and privileges

All roles are `NOLOGIN`. Each environment's login users are granted membership outside
migrations (Phase 15). Tests switch roles with `SET ROLE`.

| Role                                                                                       | Writes                                                                                                      | Reads                                                                            |
| ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `vouch_<module>` (identity, profiles, media, safety, matching, chat, notifications, admin) | Its own schema (no `UPDATE` on `admin.audit_log`)                                                           | Its own schema, every published view, `platform.feature_flags`, `platform.inbox` |
| every module role above                                                                    | `INSERT` on `platform.outbox`; `INSERT` on `platform.inbox`; `INSERT`/`UPDATE` on `platform.deletion_tasks` | (the outbox itself is not readable)                                              |
| `vouch_platform`                                                                           | The `platform` schema (relay, flags, retention jobs)                                                        | Every published view                                                             |
| `vouch_discovery`                                                                          | Nothing                                                                                                     | Published views only                                                             |
| `vouch_views`                                                                              | Nothing                                                                                                     | Group role holding `SELECT` on every published view                              |

No role can log in, create objects, create roles or create databases. The exact privilege
matrix is verified by `apps/api/test/db/roles.test.js`.

## Schemas and tables

### `platform` (kernel)

| Table             | Purpose                                                                     | Key                    | Notable constraints and indexes                                                             |
| ----------------- | --------------------------------------------------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------- |
| `campus_clusters` | Groups of nearby colleges; decks never cross a cluster                      | `id`                   | `name` unique                                                                               |
| `colleges`        | College with its email domains                                              | `id`                   | FK `cluster_id` → `campus_clusters` (same schema, low volume); GIN index on `email_domains` |
| `outbox`          | Transactional outbox for domain events (`noun.verb.vN`)                     | `id` bigserial         | `name` format CHECK; partial index on unpublished rows; index on `published_at` for cleanup |
| `inbox`           | Consumer deduplication                                                      | `(consumer, event_id)` | Index on `processed_at` for cleanup                                                         |
| `feature_flags`   | Flag rules (campus, cohort, percentage, platform, app version, kill switch) | `key`                  | `rules` must be a JSON array                                                                |
| `deletion_tasks`  | Per-module account-erasure progress (Phase 10)                              | `(user_id, module)`    | Partial index on open tasks                                                                 |

View `platform.colleges_v`: active colleges (`id, name, email_domains, cluster_id, city`).

### `identity`

| Table           | Purpose                                             | Key                                           | Notable constraints and indexes                                                                                                  |
| --------------- | --------------------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `users`         | Account                                             | `id`; `public_id` unique; `email_hmac` unique | `status` in `pending, pending_review, active, banned, deleted`; 18+ CHECK; `status = 'deleted'` exactly when `deleted_at` is set |
| `devices`       | Signed-in device, push token                        | `id`                                          | FK `user_id` → `users`; unique active `push_token`                                                                               |
| `auth_sessions` | Refresh token (hash only), rotation chain           | `id`; `token_hash` unique                     | FK `user_id`, `device_id`; indexes on `family_id`, `user_id`, `expires_at`                                                       |
| `consents`      | Privacy-notice version and purposes accepted (DPDP) | `id`                                          | FK `user_id`; at least one purpose                                                                                               |

View `identity.active_users_v`: users who may appear to others (`id, public_id, college_id`).

### `profiles`

| Table              | Purpose                                                                          | Key               | Notable constraints and indexes                                                                                                                                                                                                                              |
| ------------------ | -------------------------------------------------------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `profiles`         | Dating profile and preferences                                                   | `user_id`         | `status` in `pending, active, hidden`; age range 18–99 with `min_age <= max_age`; `name`/`gender` nullable until the profile is active; `birth_date` copied from identity; partial index `(cluster_id, gender, last_active_at DESC) WHERE status = 'active'` |
| `photos`           | Photo metadata; bytes live in R2                                                 | `id`              | FK `user_id` → `profiles`; `position` 0–5; approved photos must have both variant keys                                                                                                                                                                       |
| `profile_sections` | Extension point 9: typed sections (`jsonb`), validated by registered zod schemas | `(user_id, type)` | FK `user_id` → `profiles`                                                                                                                                                                                                                                    |

View `profiles.candidates_v`: active profiles with the fields discovery filters and scores on,
plus `approved_photos`. No names, bios or photo keys.

### `media`

| Table     | Purpose                    | Key                    | Notable constraints and indexes                            |
| --------- | -------------------------- | ---------------------- | ---------------------------------------------------------- |
| `uploads` | Presigned upload lifecycle | `id`; `raw_key` unique | Content type in `jpeg, png, webp`; `max_bytes` up to 10 MB |

### `safety`

| Table                  | Purpose                                      | Key                        | Notable constraints and indexes                                                                                                                                                           |
| ---------------------- | -------------------------------------------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `blocks`               | Directional block (symmetric for visibility) | `(blocker_id, blocked_id)` | No self-block; index on `blocked_id`                                                                                                                                                      |
| `reports`              | Report with evidence snapshot                | `id`                       | `context` in `profile, chat`; `status` in `open, actioned, dismissed`; `closed_at` set exactly when not open; queue index `(status, created_at)`; `(target_id, created_at)` for auto-hide |
| `bans`                 | Ban with optional expiry                     | `id`                       | One active ban per user                                                                                                                                                                   |
| `verification_reviews` | ID-card fallback queue                       | `id`                       | One pending review per user; decision fields set together                                                                                                                                 |

View `safety.block_pairs_v`: every block in both directions (`user_id, other_id`).

### `matching`

| Table     | Purpose                                                                          | Key                                  | Notable constraints and indexes                                                                                                                                     |
| --------- | -------------------------------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `swipes`  | Likes and passes; `PARTITION BY HASH (swiper_id)`, 16 partitions `swipes_p0…p15` | `(swiper_id, target_id)`             | `direction` 1 = like, 0 = pass; no self-swipe; partial `(target_id, created_at) WHERE direction = 1`; partial `(created_at) WHERE direction = 0` for pass retention |
| `matches` | Match in canonical order                                                         | `id`; unique `(user_low, user_high)` | `user_low < user_high`; `unmatched_at`; `anonymised_at`                                                                                                             |

Views: `matching.seen_v` (`swiper_id, target_id`) and `matching.likes_in_v` (`user_id`,
`swiper_id`, `created_at` for incoming likes). Users only ever see like counts in v1.

### `chat`

| Table           | Purpose                                                                | Key                          | Notable constraints and indexes                                                                                                    |
| --------------- | ---------------------------------------------------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `conversations` | One per match                                                          | `id`; unique `match_id`      | Pair copied from the match (`user_low < user_high`) for membership checks; `last_seq >= 0`; index on `closed_at` for retention     |
| `messages`      | `PARTITION BY HASH (conversation_id)`, 16 partitions `messages_p0…p15` | `(conversation_id, seq)`     | Unique `(conversation_id, client_msg_id)`; `kind` is open-ended text; body or media key required; index on `sender_id` for erasure |
| `read_cursors`  | One read/delivered cursor per user per conversation                    | `(conversation_id, user_id)` | FK `conversation_id` → `conversations`                                                                                             |

### `notifications`

| Table        | Purpose                                   | Key                       | Notable constraints and indexes                           |
| ------------ | ----------------------------------------- | ------------------------- | --------------------------------------------------------- |
| `prefs`      | Push preferences and quiet hours          | `user_id`                 | Quiet hours: both ends or neither                         |
| `deliveries` | Delivery log; never stores message bodies | `id`; unique `dedupe_key` | `status` in `queued, sent, failed, suppressed, cancelled` |

### `admin`

| Table         | Purpose                             | Key                       | Notable constraints and indexes                                                                                               |
| ------------- | ----------------------------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `admin_users` | Moderator and admin accounts        | `id`; unique `email_hmac` | MFA enabled only with a stored (encrypted) TOTP secret                                                                        |
| `audit_log`   | Append-only record of admin actions | `id`                      | `details` must be a JSON object; the admin role cannot `UPDATE` it; no FK to `admin_users` so entries survive account removal |

## Retention

> ⚖️ **Every row below is marked for legal review in Phase 14** (DPDP Act and Rules; see
> `docs/ARCHITECTURE.md` 11.4). Values marked _proposed_ were not in the approved list and
> need the owner's confirmation. The jobs that enforce retention are built in the phase that
> owns each table.

| Data                                                              | Kept for                                                                    | Mechanism                                                      |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Passes (`swipes`, `direction = 0`)                                | 30 days                                                                     | Nightly batched delete per partition (Phase 8)                 |
| Likes (`swipes`, `direction = 1`)                                 | Account lifetime                                                            | Deleted on account deletion                                    |
| Matches                                                           | Account lifetime                                                            | Anonymised on account deletion (tombstone id, `anonymised_at`) |
| Messages                                                          | Until account deletion, or conversation closed (unmatch or block) + 30 days | Erase handler and nightly purge (Phase 9)                      |
| Report evidence (`reports`)                                       | 1 year after `closed_at`                                                    | Nightly purge (Phase 10)                                       |
| Bans                                                              | While active                                                                | Removed once lifted or expired (Phase 10)                      |
| Audit log                                                         | 2 years                                                                     | Nightly purge (Phase 10)                                       |
| Published outbox rows                                             | 7 days                                                                      | Nightly job (Phase 4)                                          |
| Inbox rows                                                        | 30 days                                                                     | Nightly job (Phase 4)                                          |
| Expired or revoked sessions                                       | 30 days after expiry or revocation                                          | Nightly job (Phase 5)                                          |
| Revoked devices                                                   | 30 days after revocation (_proposed_)                                       | Nightly job (Phase 5)                                          |
| Consent records                                                   | Account lifetime (_proposed_)                                               | Erased with the account                                        |
| Notification deliveries                                           | 90 days                                                                     | Nightly job (Phase 10)                                         |
| ID-card images (`verification_reviews.id_image_key`)              | 30 days after the decision                                                  | R2 delete + key cleared (Phase 10)                             |
| Upload rows (`media.uploads`)                                     | 7 days                                                                      | Nightly job (Phase 6)                                          |
| Raw upload objects (R2 `uploads/raw/`)                            | 1 day                                                                       | R2 lifecycle rule (Phase 15)                                   |
| OTP codes                                                         | 10 minutes                                                                  | Redis TTL (Phase 5)                                            |
| Deleted accounts                                                  | Hard-deleted 30 days after soft delete                                      | `user.deleted.v1` drives every module's erase handler          |
| Account deletion tasks                                            | 90 days after completion (_proposed_)                                       | Nightly job (Phase 10)                                         |
| Disabled admin accounts                                           | 2 years, matching the audit log (_proposed_)                                | Manual (Phase 10)                                              |
| Profiles, photos, sections, prefs, blocks, verification decisions | Account lifetime                                                            | Erased on account deletion                                     |
| Colleges, clusters, feature flags                                 | Indefinitely (not personal data)                                            | —                                                              |

## Seed data

`pnpm db:seed` (`apps/api/scripts/seed.js`) creates synthetic data for local development and
tests only. It refuses to run with `NODE_ENV=production`.

- 1 cluster, 2 colleges with reserved `*.example.edu` domains.
- 2,000 active adult users with profiles and 2–4 approved placeholder photos each.
- Deterministic: one fixed seed drives a seeded generator, so ids and values never change.
- Idempotent: every insert uses `ON CONFLICT DO NOTHING`; running it twice changes nothing.
